Интернетp - всемирная компьютерная сеть. Работающая на стеке протоколов TCP/IP.
---
Компоненты интернета - 1)Организации(ISOC), 2)Службы(DNS), 3)Стек TCP/IP, 4)Документация(RFC)
---
Клиент-серверная архитектура (какие есть типы взаимодействия) - программа, состоящая из двух компонентов(Клиента и Сервера). Они взаимодействуют между собой по определенным правилам(протоколам)
Дуплекс(одновременно два), Полудуплекс(очередь), Симплекс(только один отправляет, а второй принимает), Pub(один публикует, а подписчики получают. Публикующий не знает кто подписан)
---
Веб-приложение понятие - клиент-серверное приложения применяющее для обмена данными протокол HTTP. Может быть приложением(html+http) или службой(api, xml, json, транспорт)
---
Свойства http (тут также кратко про отличие версий) -
HTTP 1.0 - полудуплекс, действующий(текстовый)
HTTP 1.1 - полудуплекс, бинарный
HTTP 2.0 - дуплекс
HTTP 3.0 - черновой, не распространен
Свойства:
Только два абонента (клиент и сервер)
Только два типа сообщений (request и response)
От клиента к серверу - request
От сервера к клиенту - response
На один request один response и наоборот. Иначе ошибка
TCP-порты 80(HTTP), 443(HTTPs)
Для адресации используется URI или URN;
Поддерживается W3C, описан в нескольких RFC.

Что такое stateless протокол - протокол, который не сохраняет данные о предыдущих запросах, каждый запрос изолирован от другого
---
HTTPS (процедура рукопожатия) - HTTPs ето защищенная версия  HTTP, использующая шифрование для обеспечения конфиденциальности и целости при передачи данных (К-С)
Рукопожатие - процесс согласования параметров и установления соединения между сервером и клиентом.
Инициация: Клиент запрашивает защищенное соединение (HTTPS).
Сертификат: Сервер отправляет свой SSL/TLS сертификат с публичным ключом.
Проверка: Клиент проверяет подлинность сертификата через CA.
Генерация ключа: Клиент создает предварительный сеансовый ключ и шифрует его публичным ключом сервера.
Отправка ключа: Клиент отправляет зашифрованный ключ на сервер.
Дешифровка: Сервер дешифрует ключ с помощью своего приватного ключа.
Установка ключа: Оба устройства имеют общий сеансовый ключ.
Завершение: Клиент и сервер подтверждают завершение рукопожатия и начинают обмен зашифрованными данными.

Группы заголовков
General: общие заголовки, используются в запросах и ответах;
Request: используются только в запросах;
Response: используются только в ответах;
Entity: для сущности в ответах и запросах.

Методы запроса
GET - запрашивает данные с сервера
PATСH - частично обновляет ресурс
CONNECT - устанавливает туннель к серверу
HEAD - запрашивает заголовок ответа без тела
POST - отправляет данные на сервер для обработки
DELETE - удаляет указанный ресурс с сервера
TRACE - возвращает данные, отправленные клиентом, для диагностики
OPTIONS - запрашивает информацию о поддерживаемых методах для ресурса
PUT - обновляет существующий ресурс или создает новый

Структура uri
URL(Uniform Resource Location) - унифицированный локатор сервиса, содержит местонахождение ресурса и способ обращения(протокол) к ресурсу, описывает множество URI
URN(Uniform Resource Name) - унифицированное имя ресурса, не содержащее его местоположения и способа доступа к ресурсу.
(В будущем должно решить проблему с перемещением ресурсов в Internet)

Идемпотентность - свойство операций, которое означает, что повторное выполнение операции с такими же данными даст тот же результат, что и первое выполнение

Жизненный цикл сессии
Создание. Пользователь заходит на сайт или входит в аккаунт. Сервер создаёт сессию и выдаёт её идентификатор.
Сохранение идентификатора. Обычно браузер хранит его в cookie, например session_id=abc123.
Использование. Браузер отправляет cookie со следующими запросами. Сервер по идентификатору находит сессию и понимает, кто обратился.
Завершение. Сессия заканчивается после выхода из аккаунта, истечения срока действия или удаления сервером. Старый идентификатор перестаёт давать доступ.

Что такое фреймворк?
Фреймворк - набор библиотек и правил их применения
---
Что такое фреймворк  операционной системы?
Фреймворк ОС - набор библиотек и правил их применения, который облегчает разработку ПО, предоставляет доступ к ресурсам системы и стандартным методам взаимодействия с ОС
---
Что такое программная платформа?
Программная платформа - совокупность ОС, фреймворков и библиотек, обеспечивающая среду для разработки и выполнения ПО
---
Что такое .NET?
.NET - модульная платформа для разработки ПО с открытым исходным кодом
---
Что такое ASP.NET CORE?
ASP.NET CORE - кроссплатформенны фреймворк для разработки ПО на платформе .NET
---
Что означает, что ASP.NET CORE является кроссплатформенной?
Кроссплатформенный - означает имеет поддержку на разных архитектурах и типах ОС, Windows, Linux, MacOS. Это работает благодаря CLR, который преобразовывает код в единый формат
---
Что такое NuGet?
NuGet - пакетный менеджер платформы .NET, который облегчает установку/обновление/управление библиотек и тд.
---
Для чего нужна утилита dotnet?
dotnet - Команда командной строки для платформы .NET, используемая для создания, сборки, запуска приложений и управления пакетами.

Что такое CoreCLR?
Реализация среды выполнения .NET, которая обеспечивает выполнение приложений на платформе .NET Core. Она отвечает за управление памятью, сборку мусора и выполнение кода, обеспечивая кроссплатформенную поддержку и высокую производительность.

Что такое CoreFX?
Набор библиотек классов для .NET Core, который предоставляет основные функции и API для разработки приложений.

Как называется встроенный в ASP.NET CORE http-сервер?
ASP.NET CORE: Kestrel – кроссплатформенный HTTP-сервер, принимает низкоуровневый запрос, и на его основе создаёт объект HttpContext, содержащий всю информацию о запросе (в т.ч. Request и Response). Альтернатива  Kestrel: IIS HTTP Server (только под Windows) и HTTP.sys (только под Windows).        
Стадии (этапы) подготовки и запуска ASPA.
- generate – создание приложения на основе шаблона;
