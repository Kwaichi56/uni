# Ответы по твоему проекту

## 1. Как привязать объект к методу
В WPF объект обычно привязывается к методу не напрямую, а через **Command** или через обработчик события.

### Вариант 1. Через Command
Это основной и правильный способ для MVVM.

Пример:
```xml
<Button Content="В корзину"
        Command="{Binding AddToCartCommand}"
        CommandParameter="{Binding}" />
```

Что здесь происходит:
- `Command` — указывает, какую команду вызвать.
- `CommandParameter="{Binding}"` — передает в команду текущий объект, например товар `Product`.

То есть при нажатии кнопки в команду передается сам объект товара.

### Вариант 2. Через событие
Можно сделать так:
```xml
<Button Click="Login_Click"/>
```

И в code-behind:
```csharp
private void Login_Click(object sender, RoutedEventArgs e)
{
    // код
}
```

Но для твоей работы лучше говорить, что **основные действия реализованы через Command**, потому что это прямо требуется по заданию.

***

## 2. Как создать стили и как они применяются
Стиль в WPF — это набор свойств оформления для элементов интерфейса.

### Стиль без ключа
```xml
<Style TargetType="Button">
    <Setter Property="Background" Value="Blue"/>
    <Setter Property="Foreground" Value="White"/>
</Style>
```

Такой стиль автоматически применяется **ко всем кнопкам** в области видимости ресурса.

### Стиль с ключом
```xml
<Style x:Key="ProductTitleTextStyle" TargetType="TextBlock">
    <Setter Property="FontSize" Value="20"/>
    <Setter Property="FontWeight" Value="Bold"/>
</Style>
```

Применяется так:
```xml
<TextBlock Style="{StaticResource ProductTitleTextStyle}" />
```

### Где хранятся стили
Обычно стили выносят в отдельные словари ресурсов:
- `Colors.xaml`
- `Controls.xaml`

### Как объяснить
- без `x:Key` — стиль по умолчанию для всех элементов данного типа;
- с `x:Key` — стиль применяется только там, где его явно указали.

## 3. Где реализован паттерн Command
Паттерн Command у тебя реализован через:
- интерфейс `ICommand`,
- класс `RelayCommand`,
- команды во `ViewModel`.

### Где именно
#### `RelayCommand.cs`
Это универсальная реализация команды.

#### `MainViewModel.cs`
Там создаются конкретные команды:
```csharp
public ICommand AddToCartCommand { get; }
public ICommand AddProductCommand { get; }
public ICommand DeleteProductCommand { get; }
public ICommand SaveProductsCommand { get; }
```

Инициализация:
```csharp
AddToCartCommand = new RelayCommand(p => AddToCart(p as Product));
```

### Смысл
- кнопка не вызывает метод напрямую;
- она вызывает объект команды;
- команда уже запускает нужную бизнес-логику.

## 4. Как реализуется перевод на странице
Перевод сделан через **Resource Dictionary** и `DynamicResource`.

### Где лежат переводы
Например:
- `Strings.ru-RU.xaml`
- `Strings.en-US.xaml`

Внутри:
```xml
<sys:String x:Key="LoginTitle">Вход в систему</sys:String>
<sys:String x:Key="LoginButton">Войти</sys:String>
```

Английский:
```xml
<sys:String x:Key="LoginTitle">Login</sys:String>
<sys:String x:Key="LoginButton">Sign In</sys:String>
```

### Как используется в XAML
```xml
<TextBlock Text="{DynamicResource LoginTitle}" />
<Button Content="{DynamicResource LoginButton}" />
```

### Как меняется язык
При нажатии на кнопку языка:
- старый словарь ресурсов удаляется,
- новый словарь подключается,
- интерфейс автоматически обновляет тексты.

### Как сказать на защите
“Локализация реализована через ResourceDictionary. Тексты вынесены в отдельные словари для русского и английского языка. На элементах используются DynamicResource, поэтому при замене словаря ресурсы интерфейса обновляются динамически.”

# Ответы на теоретические вопросы

## 1. Перечислите преимущества и недостатки WPF

### Преимущества
- Удобная работа с интерфейсом через XAML.
- Есть мощная система привязки данных.
- Поддерживаются стили, шаблоны, ресурсы, анимации.
- Удобно использовать паттерн MVVM.
- Можно создавать сложные и современные desktop-интерфейсы.
- Хорошо подходит для больших приложений.

### Недостатки
- Высокий порог входа.
- Сложнее, чем WinForms.
- Много специфических механизмов: Binding, DependencyProperty, Routed Events.
- Требует аккуратной архитектуры.
- Ориентирован в первую очередь на Windows.

### Короткий ответ
WPF удобен для создания сложных и красивых desktop-приложений, но требует более глубокого понимания архитектуры и механизмов платформы.

## 2. Зачем нужен язык XAML? Каким образом он используется в WPF?
XAML — это язык разметки, который используется для описания интерфейса в WPF.

С его помощью задают:
- окна;
- элементы управления;
- контейнеры;
- стили;
- шаблоны;
- привязки;
- ресурсы.

### Зачем он нужен
Он отделяет внешний вид интерфейса от логики программы.

### Как используется
Обычно:
- интерфейс пишется в `.xaml`;
- логика — в `.xaml.cs` или во ViewModel.

### Пример
```xml
<Button Content="Войти" Width="120" Height="40"/>
```

## 3. Какие бывают контейнеры компоновки?
Основные контейнеры компоновки в WPF:

### 1. Grid
Самый универсальный контейнер. Размещает элементы по строкам и столбцам.

### 2. StackPanel
Располагает элементы вертикально или горизонтально.

### 3. DockPanel
Прижимает элементы к сторонам контейнера: сверху, снизу, слева, справа.

### 4. WrapPanel
Располагает элементы в строку с переносом.

### 5. Canvas
Позволяет задавать точные координаты элементов.

### 6. UniformGrid
Размещает элементы в одинаковых ячейках.

### Коротко
Для сложных интерфейсов чаще всего используют `Grid`, `DockPanel` и `StackPanel`.

## 5. Объясните назначение класса DependencyProperty. Зачем нужны свойства зависимостей? Как создать новое свойство зависимости и в каких случаях это необходимо?

### Что это такое
`DependencyProperty` — это специальный тип свойства в WPF, который нужен для участия в механизмах платформы.

Обычное C#-свойство этого не умеет.

### Зачем нужны свойства зависимостей
Они поддерживают:
- Binding;
- стили;
- шаблоны;
- анимации;
- наследование значений;
- уведомление системы об изменениях.

### Пример создания
```csharp
public static readonly DependencyProperty MyTextProperty =
    DependencyProperty.Register(
        "MyText",
        typeof(string),
        typeof(MyControl),
        new PropertyMetadata(""));

public string MyText
{
    get => (string)GetValue(MyTextProperty);
    set => SetValue(MyTextProperty, value);
}
```

### Когда это нужно
Когда создается свой собственный элемент управления и его свойство должно:
- участвовать в привязке;
- изменяться через стиль;
- использоваться в шаблоне;
- анимироваться.

## 6. Каким образом осуществляется обработка событий в WPF? Что означает концепция маршрутизированных событий? Перечислите основные группы событий.

### Как обрабатываются события
Есть два основных способа:
- через обработчики событий в code-behind;
- через команды.

Пример:
```xml
<Button Click="Login_Click"/>
```

### Что такое маршрутизированные события
Это события, которые проходят по дереву элементов, а не остаются только внутри одного элемента.

### Виды маршрутизации
#### 1. Bubbling
Событие идет от внутреннего элемента вверх к родительским.

#### 2. Tunneling
Событие идет сверху вниз. Обычно имеет префикс `Preview`.

#### 3. Direct
Обычное прямое событие, без маршрута.

### Основные группы событий
- события мыши;
- события клавиатуры;
- события фокуса;
- события загрузки;
- события изменения состояния элементов.

## 7. Что такое Resource Dictionary?
`ResourceDictionary` — это словарь ресурсов WPF.

В нем можно хранить:
- строки;
- стили;
- кисти;
- шаблоны;
- конвертеры;
- изображения;
- другие переиспользуемые объекты.

### Зачем нужен
Чтобы не дублировать одинаковые данные и централизованно управлять ресурсами приложения.

### Примеры использования
- стили интерфейса;
- цвета темы;
- локализация;
- шаблоны элементов.

## 8. Что такое стиль и как его создать? В чем преимущество использования стиля?
Стиль — это набор настроек внешнего вида элемента.

### Пример
```xml
<Style TargetType="Button">
    <Setter Property="Background" Value="Blue"/>
    <Setter Property="Foreground" Value="White"/>
    <Setter Property="Padding" Value="10,5"/>
</Style>
```

### Как создать
Стиль можно создать:
- в ресурсах окна;
- в `App.xaml`;
- в отдельном файле словаря ресурсов.

### Преимущества
- единый внешний вид;
- меньше дублирования кода;
- проще менять дизайн;
- удобнее поддерживать проект;
- легко применять ко многим элементам сразу.

## 9. Что такое Command? Расскажите паттерн Command. Как в WPF используется Command и для чего?
`Command` — это объект, который инкапсулирует действие.

### Смысл паттерна Command
Вместо прямого вызова метода кнопка работает через объект-команду.

Это позволяет:
- отделить интерфейс от логики;
- сделать код чище;
- лучше поддерживать MVVM;
- управлять доступностью действий.

### В WPF команда основана на `ICommand`
У команды есть:
- `Execute` — выполнить действие;
- `CanExecute` — можно ли выполнить действие;
- `CanExecuteChanged` — событие изменения доступности.

### Пример
```csharp
AddToCartCommand = new RelayCommand(
    p => AddToCart(p as Product),
    p => p is Product
);
```

И в XAML:
```xml
<Button Command="{Binding AddToCartCommand}"
        CommandParameter="{Binding}"/>
```

### Для чего используется
- для добавления в корзину;
- для удаления товара;
- для сохранения;
- для смены языка;
- для оформления заказа.
