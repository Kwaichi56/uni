# Ответы на вопросы лабораторной работы 9

1. **ORM** — отображение объектов программы на таблицы, строки и связи реляционной БД.
   При чтении ORM создаёт объекты, при сохранении преобразует их изменения в команды БД.

2. **Зачем ORM:** меньше однотипного кода, единая модель и отслеживание изменений,
   удобная работа со связями и миграциями. Недостатки — дополнительный слой,
   необходимость понимать генерируемый SQL, возможные лишние запросы и сложность
   точной оптимизации. Для трудных запросов всё равно нужно знать SQL и план выполнения.

3. **Entity Framework** — ORM для .NET от Microsoft. В проекте используется EF Core
   с провайдером SQLite.

4. **EDM** в классическом EF описывает концептуальную модель (CSDL), схему хранения
   (SSDL) и сопоставление между ними (MSL). В EF6-дизайнере эти части содержатся в
   `.edmx`. EF Core использует классы, метаданные модели и конфигурацию; файла
   `.edmx` у него нет.

5. **Способы создания модели:** Code First — классы и конфигурация определяют схему;
   Database First — сущности и контекст получают из существующей БД; Model First в
   EF6 — рисуют модель в EDMX-дизайнере и генерируют из неё базу. Примеры шагов есть
   в `MODEL_GENERATION.md`.

6. **Отличия EF:** `DbContext`, отслеживание изменений, LINQ to Entities,
   навигационные свойства, загрузка связей, миграции и поддержка разных СУБД через
   провайдеры. В отличие от ручного ADO.NET разработчик обычно работает с объектами,
   а не собирает команды для каждой операции.

7. **DbContext** представляет рабочую сессию с БД: содержит `DbSet<T>`, строит
   запросы, отслеживает сущности и сохраняет изменения через `SaveChanges`.
   Его создают на короткую операцию и освобождают (`using`/`await using`).

8. **Аннотации Code First** — атрибуты вроде `[Required]`, `[MaxLength]`,
   `[Key]` на свойствах класса. Они задают ограничения и отображение близко к
   сущности, но не все настройки удобно выразить атрибутами.

9. **Fluent API** настраивается в `OnModelCreating`: `HasKey`, `HasIndex`,
   `HasMany`, `WithOne`, `HasForeignKey`, `OnDelete`. В этом проекте оно
   задаёт уникальность категории и логина, связи и правила удаления.

10. **Загрузка связанных данных:** eager (`Include`/`ThenInclude` вместе с
    основным запросом), explicit (`Entry(...).Collection(...).LoadAsync()` по
    запросу), lazy (при специальной настройке прокси или ILazyLoader). Здесь
    `GetProductsAsync` использует `Include(p => p.Category)`.

11. **Code First и Database First:** в первом случае исходником схемы служит
    объектная модель; во втором исходником служит существующая БД. Обновление
    классов при Database First выполняется повторным scaffolding, при Code First
    изменения модели обычно оформляют миграциями.

12. **Миграции** сохраняют последовательность изменений схемы и позволяют
    обновлять БД без пересоздания. Типовой порядок: установить EF Core Design и
    `dotnet-ef`, выполнить `dotnet ef migrations add InitialCreate`, затем
    `dotnet ef database update`. В текущей учебной работе новая БД создаётся
    `EnsureCreatedAsync`; для перехода на миграции нужна новая БД или отдельный
    согласованный план перехода, поскольку `EnsureCreated` не ведёт историю миграций.

13. **CRUD через EF:** создать `DbContext`; для просмотра выполнить запрос к
    `DbSet<T>` с `Where`/`Select`/`ToListAsync`; для добавления вызвать
    `Add`; для редактирования загрузить запись и изменить её свойства; для удаления
    вызвать `Remove`; завершить `SaveChangesAsync`. Связанные действия вроде
    заказа и уменьшения остатка выполняются внутри одной транзакции.
