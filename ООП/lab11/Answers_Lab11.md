# Ответы на вопросы к лабораторной работе 11

1. **MVC, MVP, MVVM.** MVC разделяет модель, представление и контроллер: контроллер обрабатывает ввод и выбирает действие над моделью/представлением. MVP вводит Presenter, который управляет пассивным View через интерфейс. MVVM вводит ViewModel — состояние и действия интерфейса, связанные с View привязками данных и командами. В WPF это позволяет оставить в XAML большую часть синхронизации интерфейса с состоянием.

2. **Компоненты MVVM.** Model хранит предметные данные и правила. View отображает их и получает ввод пользователя. ViewModel предоставляет свойства, коллекции и команды для View, обращается к модели и сервисам, но не содержит ссылок на конкретные элементы окна. В этой работе пример цепочки: `Product` → `MainViewModel.ProductsView` → `ListBox` каталога.

3. **Реализация в WPF.** View получает ViewModel через `DataContext`. В XAML свойства связываются с `Binding`, списки — с `ItemsSource`, действия кнопок — с `Command`. Изменения отдельного свойства передаются через `INotifyPropertyChanged`, изменения состава списка — через `ObservableCollection<T>`. `CanExecute` управляет доступностью кнопки.

4. **`INotifyPropertyChanged`.** Интерфейс объявляет событие `PropertyChanged`. Когда ViewModel меняет значение свойства, она вызывает это событие с именем свойства, и WPF обновляет соответствующие привязки. Базовый класс проекта — `Helpers/BaseViewModel.cs`; его `OnPropertyChanged` использует `CallerMemberName`.

5. **`ICommand`.** Интерфейс задаёт `Execute`, `CanExecute` и `CanExecuteChanged`. WPF вызывает команду при нажатии кнопки и отключает кнопку, когда `CanExecute` возвращает `false`. В проекте `RelayCommand` реализует этот контракт; например, `SaveCartCommand` доступна лишь при наличии товаров в корзине.

6. **Команда и событие.** Событие сообщает, что произошло с конкретным элементом (`Click`, `SelectionChanged`); подписчик сам решает, что делать. Команда представляет намерение пользователя как действие ViewModel, может использоваться несколькими элементами и содержит проверку доступности через `CanExecute`. События остаются уместными для сугубо визуальных задач, например настройки столбцов `DataGrid`.

7. **Библиотеки.** MVVM Light Toolkit предоставлял базовые ViewModel, команды и средства обмена сообщениями; его репозиторий [архивирован](https://github.com/lbugnion/mvvmlight), а автор рекомендует CommunityToolkit.Mvvm как преемника. [Catel.MVVM](https://docs.catelproject.com/7.x/index.html) даёт базовые классы модели и ViewModel, команды, сервисы, валидацию и сопоставление модели с ViewModel. [Prism](https://prismlibrary.github.io/docs/wpf/introduction.html) рассчитан на составные WPF-приложения: включает MVVM-инфраструктуру, команды, модульность, регионы, навигацию и диалоговый сервис. Для учебного проекта достаточно собственных `BaseViewModel` и `RelayCommand`, поэтому внешняя MVVM-библиотека не добавлена.
